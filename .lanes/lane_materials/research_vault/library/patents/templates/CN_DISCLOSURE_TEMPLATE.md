# 高质量专利交底书标准模版 (High-Quality Patent Disclosure Template)

> **核心原则**：专利保护的是“技术方案”而非“算法思想”。必须强调“技术问题-技术手段-技术效果”的三性逻辑。

## 1. 著录项目 (front Matter)
*   **发明名称**：一种[技术领域/功能]的[方法/系统/装置]
    *   *示例*：一种基于拓扑一致性投影的纵向临床事件抽取系统及方法
*   **发明人**：[姓名]
*   **技术领域 (Technical Field)**：明确本申请所属的具体技术领域。

## 2. 背景技术与技术问题 (Background & Technical Problem)
*   **现有技术 (Prior Art)**：简述目前主流的解决方案（如 SFT, RLHF, 规则引擎）。
*   **技术缺陷 (Technical Defect)**：现有技术存在什么具体问题？（如：计算复杂度高、无法处理长序列、幻觉率高）。
    *   *关键*：必须客观、具体。不要说“效果不好”，要说“导致了时序逻辑冲突”。
*   **技术问题 (Technical Problem)**：基于上述缺陷，本发明要解决的核心技术问题是什么？

## 3. 技术方案 (Technical Solution) - **核心章节**
*   **总体思路**：用一句话概括核心创新点（一句话方案）。
*   **与现有技术的区别 (Distinction from Prior Art)**：**[必须]** 简要对比本方案与（1）规则方法、（2）纯深度学习方法的本质区别（例如：解耦设计、无需重训练）。
*   **系统架构图 (System Architecture)**：必须提供框图，展示模块及其连接关系。
*   **核心模块详解**：
    *   **模块 A**：功能 + 输入 + 处理逻辑（流程图） + 输出。
    *   **模块 B**：...
    *   *注意*：避免纯数学公式推导，要将公式转化为“数据处理步骤”。例如，不要仅写 $y=f(x)$，要写“处理器配置为执行函数 f 对信号 x 进行变换”。
*   **关键算法流程图 (Flowchart)**：必须包含。

## 4. 有益效果 (Beneficial Effects)
*   必须与“技术缺陷”通过逻辑闭环对应。
*   **技术指标**：提升了多少？（如 F1 Score, Latency, Memory Usage）。
*   **非显而易见性**：为什么这个效果是意料之外的？

## 5. 具体实施方式 (Embodiments)
*   至少提供 **2-3 个** 具体的应用场景。
*   **场景 1**：硬件/系统部署（如：云端 API、嵌入式医疗设备）。
*   **场景 2**：具体业务流程（如：医保审计、实时诊断辅助）。
*   *目的*：支持权利要求的范围，证明方案具有广泛的工业实用性。

## 6. 权利要求书草案 (Claims Draft)
*   **权 1 (方法)**：包含解决技术问题所必须的所有必要技术特征。
*   **权 N (系统)**：对应方法步骤的硬件/功能模块。
*   **从权**：进一步限定技术细节（具体的算法实现、参数选择）。

---

## 检查清单 (Checklist)
- [ ] 标题中是否去除了“算法”、“研究”等词汇？（应为“方法”、“系统”）
- [ ] 是否明确指出了现有技术的具体缺陷？
- [ ] 是否有两个以上的附图（架构图 + 流程图）？
- [ ] 实施例是否结合了具体场景（不仅仅是实验代码）？
- [ ] 权利要求是否形成了闭环（输入->处理->输出）？
