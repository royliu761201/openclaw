# OpenClaw 语音交互演练标准规范与事故复盘 (SOP)

> 本规范用于约束后续所有大模型端到端功能的开发与调试行为。绝不重蹈“靠老板演示发现由于内存溢出导致内核崩溃”的覆辙。

## 一、 核心惨痛教训 (What We Learned)

在过去 2 小时反复测试与宕机中，我们暴露出严重的代码鲁棒性与开发流程缺陷，总结构成 4 大教训：

### 1. 盲目投喂未知数据导致 GPU 物理崩溃 (CUDA OOM / Kernel Panic)

**错误行为**：在更改本地客户端从 `librosa` 到纯 `wave` 包后，没有在 GPU 端前置检查音频的数据维度和编码类型，直接全量送入包含两十多亿参数的 `SeamlessM4Tv2` 进行 Inference。
**深刻教训**：大模型不是普通 Web 接口。数据类型的不匹配（比如 `int16` 和 `float32`）或过长的序列会使得计算图呈指数级扩张，瞬间击穿显存上限，甚至触发主板硬件看门狗导致整机断电断网（Kernel Panic）。
**必须改进**：GPU 守护程序 `v2v_stream_daemon.py` 必须对所有入参长度实施硬截断拦截（例如，拒绝处理超过 10 秒的单包音频），并加装严格的 `try...except RuntimeError:` 显存溢出清空机制，阻止进程雪崩。

### 2. 本地网关缺乏对底层网络断流的容错

**错误行为**：遇到公司的网络防火墙或者 VPN 跳板机（100.108.106.119）偶然丢包，本地代码就直接抛出异常、崩溃退出。
**深刻教训**：物理长城和企业网波动是常态（TCP RST）。过度依赖 `nohup ssh` 是业余做法。
**必须改进**：强制废用普通 SSH。所有隧道必须配置心跳探针 (`ServerAliveInterval=10`)，且 WebSockets 客户端必须捕获 `ConnectionClosed` 并进入静默重连池，而不能把错误抛给操作端。

### 3. 未处理大模型推演中的“异步心跳休克”

**错误行为**：冷启动时大模型载入长达 50 秒，但这超出了 Uvicorn WebSockets 默认的 20 秒存活检验期，导致服务器判定这端已死，主动掐断传输。
**深刻教训**：对于重型模型的流式推送，异步通信框架底层的探针参数不能使用默认值。
**必须改进**：远端已加入 `ws_ping_interval=None`，将算力上限解开。

### 4. 演示前缺乏闭环“预飞行检查” (Pre-flight Checklist)

**错误行为**：写完代码只跑通了本地日志，就拉老板过来“外放听响”，没考虑到本地换包、远端重启后的联合化学反应，把老板和用户的耳朵当成了 QA 测试仪。
**深刻教训**：这极度浪费主理人的时间与耐心，是极不专业的开发操守。

## 二、 严格受控演练行为规范 (SOP)

从即刻起，任何涉及算力节点的功能交付，必须**强制执行**以下三级递进验证法，经证明百分之百收敛后，方可请您验收入耳：

### 🔬 第一级：防御矩阵审核（白盒代码级）

1. **边界断言 (Assert Boundary)**：任何发往 GPU 的切片包必须经过校验 (`max_duration < 8s`, `format == 16Khz PCM`)，如果超标，本地必须报错，绝不允许污染 GPU 核心。
2. **死神拦截 (OOM Guard)**：服务端核心 Inference 代码必须封装入 `try/except Exception`。任何 CUDA 报错必须在内部化解执行 `torch.cuda.empty_cache()` 并返回错误帧给客户端，**绝对禁止** Python 进程级崩塌重启。

### 🛠 第二级：Mock 灰度盲测（本地假数据级）

1. 不要一上来就连真 GPU。任何新切片逻辑写完后，在本地开启一个假装返回成功波形的 Dummy WebSocket Server。
2. 用 100 倍时速推送 1000 个乱七八糟的空音频块过去，测试客户端是否能实现稳固的收发栈排队。

### 🚀 第三级：预飞行静默全量跑批（黑盒隔离级）

1. 在向您演示之前，我必须在纯静默（Silent）模式下，调用真实 GPU 流水线进行**长达 5 轮以上的重复轰炸推演测试**。
2. 通过日志拦截确认这 5 轮中不仅“首发 TTFB 达标”，且**后台没有任何哪怕一个 Warning 或 Error**，内存显存余量水位均在安全线内。
