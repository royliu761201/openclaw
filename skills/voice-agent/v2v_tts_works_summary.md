# OpenClaw 语音架构演进与防爆战役总结 (V2V & TTS)

**文档状态**: 归档版本
**日期**: 2026-03
**涉及组件**: ChatTTS (TTS), SeamlessM4Tv2 (V2V), Mac 03 SOCKS 隧道, HTTPS/WebSocket 双通道

## 🚀 核心架构里程碑

在本次架构攻坚战中，我们彻底告别了“单机裸跑、极易崩溃、连接靠猜”的史前时代，成功将 OpenClaw 的声音执行单元 (TTS文本转语音 & V2V声声同传) 建设为了**具备生产级容灾能力与极速低延迟的高可用微服务阵列**。

### 1. 显存防雷与 OOM 护甲体系 (The "OOM Guard" Armor)

- **痛点**: 早期 GPU 直接承接长音频切片时，一旦波形稍微超出显存极限或发生截断错误，Python 进程便会触发 `CUDA OutOfMemory Error` 或 `Kernel Panic` 导致全盘崩溃，甚至卡死 8200 端口使得后续发包全部被无声拒绝（Errno 61 / Exit 255）。
- **重构战果**: 我们在 `v2v_stream_daemon.py` 的心脏推理部位实现了物理级的防爆服。
  - **异常捕获**: 用 `try...except RuntimeError` 死死网住底层 CUDA 崩溃。
  - **自愈洗胃**: 任何崩溃瞬间强制触发 `torch.cuda.empty_cache()` 以及显存垃圾回收。
  - **客户端隔离**: 客户端被强制加入 SOP 断言边界代码（限制 Chunk 在 2.0s ~ 8.0s），超长切片在到达网卡前就被直接拦截，绝不拿昂贵的 GPU 显存试错。

### 2. 打破 65535 锁死，铺设满血原生 SSH 暗道

- **痛点**: 早期依赖 Mac 03 作为跳板机，并使用 Python 版本的 SOCKS5 代理。结果遇到高频流式发包时，代理的 Socket 文件描述符瞬间被撑爆（65535 Timeout），甚至制造出大量占用隧道的隐形幽灵进程。
- **重构战果**:
  - 废弃了所有垃圾第三方跳板代理。
  - 在主控机底层使用 OpenSSH 动态端口转发（`ssh -D 10800`）接驳纯正 SOCKS5 原生暗道。
  - 配套编写了一套清道夫指令（`killall ssh / fuser -k 8200`），保证每次压测前从 Mac 内核到 Ubuntu 内核的僵尸占用被“物理级扬掉”，实现网络层零宕机的光速握手。

### 3. "流式同传" 实装落地 (12秒定律 -> 4.6秒绝杀)

- **痛点**: 如果不拆解波形，长达几十秒的翻译任务会把 GPU 活活憋死。
- **重构战果**: 在 V2V 客户端使用了 `wave` 滑动窗口机制（Sliding Window）。音频被精准切分为 5 秒一段，沿着高可用隧道像机关枪一样发射。
- **极致时效**: 在冷启动完成后的满速状态下，带有超强抗压代码的 GPU 仅需 `4.62 秒` 以及后续每帧低于秒级的延迟，就能吞噬英语片段并完美无暇地吐出纯正的中文反向波形帧。

## 🩸 鲜血换来的 SOP 铁律 ( 标准操作规范)

经过数小时排雷排错，系统总结出针对未来 AI 服务开发的“三不可原则”：

1. **白盒优先，拒绝盲猜**：遇到任何 `Connection Refused`，不再盲等代理恢复，必须打探针（`netstat` / `tail log`）搞清楚死的是本地代理、跳板机网卡还是远端端口，再下刀子。
2. **永远清理现场 (Kill First)**：在挂载任何隧道前，必须先释放旧句柄 (`kill -9 $(lsof -t -i:18200)`)，避免被僵尸进程的 `Address already in use` 暗算成 `Exit 255`。
3. **先静态阻击，后上真枪**：客户端的入参过滤是一切的基础，绝不允许未经验证的“超大炸弹包”接触任何涉及 `import torch` 的算力单元。
