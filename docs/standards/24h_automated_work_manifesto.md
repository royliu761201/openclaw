# OpenClaw 24小时无人值守自动化工作规范 (v1.0)

针对 AI Agent 在处理长耗时任务（如跨机器模型搬运、底层 C++ 编译、大规模数据处理）中出现的“进度黑盒”及“会话逃逸”问题，特制定本 24 小时铁律规范，确保任务全天候、高透明、零死角推进。

---

## 🧭 一、 5分钟主动战报准则 (Progress Heartbeat)

- **铁律**：严禁在长耗时任务期间保持沉默。
- **执行**：
  - **定时打标**：每隔 5 分钟，即便没有最终结果，也必须向用户（刘总）主动汇报当前子任务的百分比进度、字节增长、或编译日志行数。
  - **探针汇报**：汇报必须基于真实系统探针（`ls -lh`, `tail`, `ps aux`），严禁使用“正在进行中”等模糊词汇，必须给出具体数值。

## 🛡️ 二、 24小时故障自愈机制 (Auto-Self-Healing)

- **铁律**：严禁任务在后台“静默卡死”。
- **执行**：
  - **死锁判定**：若监测到 SCP/CURL 进程在 3 分钟内无文件字节增长，判定为“网络死锁”。
  - **暴力重连**：一旦判定死锁，立即执行 `pkill` 强杀僵尸进程，并自动启用替代方案（如切换镜像源、切换代理节点）重新发起任务。
  - **断路保护**：对于占用 CPU/GPU 的长进程，必须配套 `Watchdog` 监控脚本，确保进程异常退出后 10 秒内实现微服务自愈。

## ⛓️ 三、 “多核并发”与“多路回退”策略 (Parallelism & Fallback)

- **铁律**：严禁在单条链路上“吊死”。
- **执行**：
  - **并发拉取**：资源下载必须“兵分多路”，同时利用 Windows 出口机、Mac 03 备份节点、及 Mac 02 目标节点并发下载。
  - **镜像热备**：所有由于网络墙导致的下载失败，必须在 30 秒内自动切换至国内加速镜像（如 `gh-proxy`, `hf-mirror`）。

## 📝 四、 任务持久化与“零残留” (Persistence & Scrubbing)

- **铁律**：干活必须留痕，事后必须清场。
- **执行**：
  - **进度入库**：所有重要的中间产物（编译成功的二进制、下载好的模型）必须立即持久化到 `Mac 03` 备份区，并在 `task.md` 中打钩。
  - **阅后即焚**：针对 M1 NPU 等敏感资源，必须实现 ASR 按需拉起。识别任务结束后的 60 秒内，必须物理销毁内存/显存占用，严禁吃空饷。

## 💂 五、 无人值守角色操守 (Unattended Conduct)

- **铁律**：您不在时，我就是守夜人。
- **执行**：
  - 当任务进入深夜或长时间运行态，Agent 应自主完成：环境检查 -> 执行 -> 验证 -> 归档 -> 撰写次日晨报，确保刘总第二天上线看到的不是故障，而是结果。

---

> [!IMPORTANT]
> **违规处分**：凡出现 10 分钟以上无故沉默、或任务卡死而未报错自愈的情况，判定为“Agent 执行事故”。
